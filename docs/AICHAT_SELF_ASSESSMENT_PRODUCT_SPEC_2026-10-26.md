# 关系清晰卡 自测与个人成长功能说明书

本功能帮助成年用户通过 MBTI／16 型人格、性格特质和优势测评认识自己，再结合个人经历获得可用于沟通、协作和职业探索的行动建议。商业结构为：**免费基础结果 → ¥29.90 个人优势说明书 → ¥49.90 职业探索报告**。

本稿供产品、设计、开发和测试评审。功能方向来自本轮需求；价格、人群及分期为本稿建议，尚未经真实付费验证。本稿描述目标行为，不表示功能已经实现或可以立即收费。

## 1. 产品目标与已确定前提

### 1.1 用户需要完成的事情

1. 了解自己的性格偏好及程度差异。
2. 从测评和个人经历中识别有依据、可以发展的优势。
3. 知道这些特点在工作、沟通、协作中如何使用。
4. 有职业探索需求时，比较多个方向并安排现实验证行动。
5. 清楚知道免费得到什么、付费增加什么，以及付款后的交付与售后。

### 1.2 决策状态

| 项目 | 本稿采用的内容 | 状态 |
|---|---|---|
| 新增能力 | MBTI／16 型人格、性格分析、天赋与优势相关自测 | 用户明确提出 |
| 工具选择 | 优先采用成熟测评工具及其题目、计分、维度和基础解释 | 用户确认方向 |
| 商业授权 | 由业务方统一采购处理，不作为本轮功能设计的阻断点 | 用户确认前提 |
| 商业设计 | 明确免费与付费边界、付费交付和购买理由 | 用户明确提出 |
| 首批人群 | 18 岁以上、希望认识自己及改善工作和沟通方式的职场用户 | 设计假设，沿用现有成年用户基础 |
| 主商品 | ¥29.90 个人优势说明书，一次购买一份报告 | 建议测试方案 |
| 升级商品 | ¥49.90 职业探索报告，可抵扣符合条件的基础报告实付金额 | 建议测试方案 |
| 收费方式 | 单次购买，含明确范围的校准和复盘 | 建议首发方案 |

### 1.3 现有基础与本次扩展

当前项目已有原创 8 题关系应对自测、访客会话、结果计分和报告相关结构；当前说明记录的报告生成仍使用确定性 Stub，真实支付与完整权益交付尚待完成。

本次新增自我探索产品流程。用户可以完成自测和购买个人报告，无需填写关系事件或进入原有关系六字段任务。原有关系应对自测、关系清晰卡与本次功能并列，按用户选择衔接。

## 2. 功能范围与实施分期

| 阶段 | 用户可使用的功能 | 交付边界 |
|---|---|---|

首期不增加会员、自动续费、虚拟币或按聊天次数购买的商品。三项测评可以独立使用；综合报告按第 6 节要求收集输入。

## 3. 用户故事

1. 作为首次进入的用户，我希望知道每项测评解决什么问题、需要多久，以便选择适合自己的入口。
2. 作为免费用户，我希望开始前就知道哪些内容免费、哪些可选付费，以便决定是否投入时间。
3. 作为答题用户，我希望暂停后可以继续，以便利用零散时间完成测评。
4. 作为答题用户，我希望修改答案和返回上一题不会丢失进度。
5. 作为完成测评的用户，我希望免费看到该测评提供的完整基础结果和解释。
6. 作为看到接近分界结果的用户，我希望知道结果存在波动，以免把一次测试当成永久标签。
7. 作为已做过测评的用户，我希望选择已有结果继续分析，以免重复答题。
8. 作为探索优势的用户，我希望补充自己的经历，并确认系统理解是否准确。
9. 作为查看综合画像的用户，我希望分清测评分数、本人陈述和系统推断。
10. 作为考虑付费的用户，我希望看到实际报告目录、个人内容预览、价格和服务范围。
11. 作为购买用户，我希望付款后可以立即查看已经就绪的报告，并在其他设备找回。
12. 作为遇到支付异常的用户，我希望系统查清已有订单，避免重复付款。
13. 作为报告用户，我希望知道建议依据什么、在何种情况下可能不适用。
14. 作为发现解读不符合实际的用户，我希望提交一次集中校准并获得修订版本。
15. 作为准备行动的用户，我希望选择一个可以完成的小练习，并在 7 天内复盘。
16. 作为职业探索用户，我希望结合自己的技能、经历和条件比较多个方向。
17. 作为已购基础报告的用户，我希望升级时抵扣已付款项，并在购买前看到计算明细。
18. 作为需要售后的用户，我希望申请退款、纠错或查看交付处理进度。
19. 作为重视隐私的用户，我希望决定分享哪些内容，并可删除自己的经历和报告。
20. 作为运营人员，我希望管理测评、报告模板、商品及版本，并核对净付款、退款和交付结果。

## 4. 信息架构与页面

新增能力集中在现有“自测”入口。个人报告从结果页和“我的 → 我的报告”访问；原有关系清晰卡入口继续承接关系任务。

### 4.1 自测首页

页面由四部分组成：

- 正在进行：显示未完成的测评、已完成的题数和继续入口。
- 探索自己：MBTI／16 型人格、性格特质、优势探索三张卡片。
- 关系应对：保留现有关系自测入口。
- 我的结果：展示最近的基础结果和已购个人报告。

每张测评卡显示名称、用途、题数、预计耗时、完成状态和“基础结果免费”的说明。题数来自实际测评版本，耗时依据供应商资料或试测数据，不预填未经验证的“3 分钟”等承诺。

## 5. 单项测评功能

### 5.1 测评接入与版本

成熟工具可按实际能力采用原生答题、官方测评跳转后接收结果或结构化结果导入。上线的每一项工具必须明确供应商、具体版本、题目与计分来源、能获得的结果字段以及完成条件。

已有商业授权安排不等于供应商一定提供 API。产品可以选择适合的接入方式，但不得把未确认的接口或结果字段写成已可用能力。

由用户手动录入或导入的结果必须标记来源，确认后才能用于报告；不能伪装为平台原始答题结果。

### 5.2 MBTI／16 型人格

用户完成所选版本测评后，可免费查看类型、维度倾向、基本解释和结果时间。接近分界的维度按工具本身支持的方式表达，不生成未经依据的置信概率。

结果页提供沟通与工作方式的基础提示，以及继续进行性格特质或优势探索的入口。四字母类型不能单独作为能力结论或职业推荐依据。

### 5.3 性格特质分析

优先采用成熟的大五人格等工具。页面展示连续维度及解释，使用户了解程度差异、常见表现和情境影响。

没有适用常模时，不展示“超过全国 90% 用户”等百分位结论。量表分数、等级和视觉图形必须来自同一计分结果，缺失值不得填零。

### 5.4 优势探索

采用适用的成熟优势测评，并收集用户经历进行校准。页面分开表达：

- 测评指出的倾向或优势主题。
- 用户陈述的行为例子与成果。
- 综合分析提出的优势候选、适用条件及待验证事项。

免费结果展示该测评版本提供的基础结果，并突出最多 3 项值得继续探索的优势候选。深度报告增加使用条件、过度使用风险和行动建议。

### 5.5 共同交互规则

同一测评运行绑定固定版本。暂停恢复使用原版本；版本升级不静默改变已经完成的结果。计分按供应商规则或服务端确定性规则完成，AI 不自行修改计分。

未完成、作答质量不足、供应商暂时不可用分别展示真实状态。允许重试或重新测评，但不能把失败解释成用户的性格特点。

## 6. 综合画像与个人优势说明书

### 6.1 输入要求

三个入口均可独立完成并获得免费结果。首发标准版“个人优势说明书”建议采用以下最低输入：

| 输入 | 要求 | 缺失时的行为 |
|---|---|---|
| 性格特质结果 | 一份完整、来源和版本明确的结果 | 展示继续测评入口 |
| 优势测评结果 | 一份完整、来源和版本明确的结果 | 展示继续测评入口 |
| 本人经历 | 至少两段用户确认的经历，包含做了什么及发生了什么结果 | 以结构化提示帮助补充 |
| 当前应用目标 | 至少选择沟通、协作、工作安排或学习中的一个 | 请求选择目标 |
| MBTI／16 型人格结果 | 可选，完成后纳入；未完成不阻止标准版 | 明确列为未纳入，不虚构类型 |

本项最低输入是本稿的产品建议：避免三个工具必须一次全部做完，也确保付费报告有足够个人信息。购买页只列实际纳入的测评，不把可选项描述成已完成服务。

用户可以主动选择已有结果组合成报告快照；各结果保留来源、版本和测评日期。新测评不覆盖旧报告，也不自动从其他聊天中更新画像。

### 6.2 个人经历采集

采用可编辑的结构化表单，每段经历包含“发生了什么、我做了什么、结果如何、哪些部分更有能量或更费力”。允许补充他人反馈，但需标明其为用户转述。

系统先整理经历，再请用户确认。本人确认只表示转述准确，不表示事件经过外部独立核验。测评数据、本人陈述、系统推断在报告中保持可区分。

### 6.3 免费与付费边界

| 内容 | 免费 | 个人优势说明书 |
|---|---|---|
| 已完成单项测评的基础结果及解释 | 完整提供 | 可引用，不重复收费 |
| 候选优势与简要来源 | 提供 | 展开分析 |
| 一个基础验证练习 | 提供 | 增加个性化步骤与观察标准 |
| 测评之间的一致与差异 | 简要提示 | 结合个人经历解释 |
| 优势适用环境与容易消耗的环境 | 概述 | 结合当前目标具体分析 |
| 优势过度使用、盲点和替代做法 | — | 提供 |
| 沟通／协作／工作安排应用 | — | 提供选定场景的具体建议 |
| 个人行动计划 | — | 最多 3 项，用户自主选择 |
| 一次结果校准与 7 天复盘 | — | 包含，不另收费 |
| 已购报告重复查看及保存 | — | 不重复收费 |

### 6.4 付费报告目录

1. **这份报告基于什么**：所用测评、日期、版本、本人确认信息及未纳入内容。
2. **我的性格与行为画像**：主要特质、不同结果之间的一致点与差异。
3. **值得发展的三项优势**：每项的来源、行为依据、适用条件和证据缺口。
4. **我容易发挥与容易消耗的环境**：任务节奏、协作方式、信息形式等具体条件。
5. **优势过度使用与盲点**：什么情况下可能失效，以及可尝试的调整。
6. **我的场景建议**：围绕用户选定的沟通、协作、工作或学习目标。
7. **未来七天的行动**：每项说明行动、投入、可观察结果和停止或调整条件。
8. **校准与复盘**：用户可以指出不符合的解释，并记录行动后的新证据。

重要结论必须指向输入依据，或者明确标为待验证假设。不得编造用户经历、职业资质、收入、常模位置或确定性的天赋结论。两位类型相同但经历和目标不同的用户，应在场景建议与行动部分体现实际差异。

## 7. 商业商品与付费逻辑

### 7.1 商品定义

| 商品 | 建议测试价 | 交付 | 购买条件 |
|---|---:|---|---|
| 单项测评基础结果 | ¥0 | 第 5 节定义的基础结果 | 对应测评有效完成 |
| 个人优势说明书 | ¥29.90 | 第 6.4 节完整报告、一次校准及 7 天复盘 | 输入满足要求，完整报告已就绪 |
| 职业探索报告 | ¥49.90 | 包含个人优势内容及第 9 节职业交付 | 职业输入齐全，完整报告已就绪 |
| 职业探索补差升级 | 标准价下补 ¥20.00 | 在符合条件的基础报告上增加职业交付 | 本人有效已购基础报告、同一基础结果快照 |
| 原有关系清晰卡 | 原规格 ¥19.90 | 一件具体关系事件的固定交付 | 按原有关系任务流程 |

价格是产品测试提案，不代表已发布的售价或已证明的用户支付意愿。成交时以服务端有效商品和价格版本为准，购买页展示完整实付金额。

### 7.2 用户付费的理由

免费层完成“认识自己”的基本承诺，也让用户判断结果是否值得继续探索。付费层承担个人信息整合、解释差异、场景应用、行动设计及后续校准，交付可以逐项核对。

单次购买对应一个明确结果和有限服务窗口，便于用户理解，也便于控制成本及售后。职业升级增加兴趣、价值观、技能和现实条件等新的分析工作；它不只是给人格类型附上职业名称。

### 7.3 转化流程

用户开始测评前即可看到免费和付费说明。完成后先展示基础结果，再邀请其补充个人经历、查看候选优势和深度报告预览。

只有用户主动请求深度报告预览时，才生成完整报告；系统确认结构和内容可交付后，展示购买入口。免费测评完成不自动触发每人一份昂贵的完整 AI 报告生成。

购买页同时展示实际纳入内容、真实预览、完整目录、一次性价格、校准和复盘范围、售后入口，并提供“继续免费使用”。通用示例标为示例，不冒充该用户的报告。

### 7.4 补差规则

补差金额 = 职业报告当前确认成交价 − 可抵扣基础报告的实际净支付金额，最低为零。标准价格下为 ¥49.90 − ¥29.90 = ¥20.00。

抵扣要求：同一用户、同一基础测评快照、基础权益有效且没有正在处理的退款。同一基础报告同时最多支持一份有效职业升级权益；已有职业权益时直接打开报告，不再下单。升级退款并撤销权益后，可按当时规则重新购买。优惠购买按实际净支付金额抵扣，不使用虚构原价抵扣。

补差为零时仍展示升级内容并由用户确认领取，记录交付与原购买的关联，不向支付渠道发起收款。

职业所需的补充答题和资料录入不再额外收费。不同经历或测评快照形成的新报告，在购买前说明其为新交付。

### 7.5 校准、复盘与重复访问

报告服务窗口从支付确认成功开始计算 7 天。包含一次集中结果校准和一次行动复盘；用户可在窗口内自主发起。系统故障导致的服务不可用应补足受影响时间。

校准主要修正经历理解和应用解释，不静默改变量表分数。用户更改量表答案时形成新的测评记录；本窗口内的一次校准可使用用户确认的新结果生成一次修订报告。处理失败不消耗校准资格。

窗口结束后，已购报告仍可重复查看和保存；结束的是本次校准与复盘服务。用户删除报告前需了解无法恢复的影响。报告内容错误修复和交付故障补救，不计为用户额外购买。

## 8. 支付、交付与售后

### 8.1 支付与权益

用户在购买前完成必要身份绑定，以便跨设备找回。已有访客结果只能通过可信的会话归属迁移至该身份。

职业报告权益包含同一快照的个人优势报告内容。直接购买职业报告的用户可查看这些基础内容，不再被引导重复购买；这不额外产生一笔基础报告订单。升级购买则保留原基础订单与权益，便于分别交付和售后。

支付成功以服务端验证的支付通知或查单事实为准。客户端成功页不能独立授予报告权益。重复点击、重复通知和网络重试不得产生重复有效权益或重复记账。

| 状态 | 用户看到什么 | 系统应做什么 |
|---|---|---|
| 报告准备中 | 进度、可返回的说明 | 不创建支付订单 |
| 报告准备失败 | 失败与重试入口 | 不扣款，不输出假报告 |
| 待支付 | 商品、金额及订单状态 | 对同一购买意图复用有效订单 |
| 支付待确认 | 正在确认支付，请勿重复付款 | 查询原支付，不按失败重开订单 |
| 支付成功、权益生效 | 查看完整报告 | 绑定本人及具体报告版本 |
| 已付款、交付异常 | 已收到付款，交付处理中，提供售后 | 自动补交付；无法完成时进入退款处理 |
| 用户取消／明确失败 | 可返回免费结果 | 只有渠道已明确终止时允许重新发起 |
| 退款处理中 | 处理状态及对应订单 | 区分申请、受理和到账 |
| 退款成功 | 已退款及保留的免费内容 | 撤销对应付费权益，保留免费结果和订单记录 |

支付适配按实际商品类别、终端及已开通的渠道能力设计。需要虚拟支付的路径使用相应能力；报告、订单和权益的业务规则保持统一。

### 8.2 售后范围

售后入口支持交付失败、重复付款、内容纠错、内容质量和隐私问题。提交时显示订单、实付、报告及问题描述；不默认索取全部个人经历。

交付失败和重复付款应主动识别并按渠道规则处理。内容质量申请进入可追踪的人工处理，不仅凭“用户已打开报告”自动拒绝。首版建议服务目标为 1 个工作日内受理、3 个工作日内给出处理结论；资金到账时间单独按渠道结果展示。

首期支持按完整商品订单退款。升级后的售后提供“仅处理升级部分”及“处理整套购买”两种范围。仅退升级部分时保留原基础报告；退整套时按两笔实际交易分别退款并撤销相应权益。直接购买职业报告后整单退款，不产生额外的付费基础权益；若另有独立有效的基础购买，则保留其权益。不能退掉被抵扣的基础款后继续保留完整职业权益而不重新核对资格。退款处理中阻止新的抵扣和重复退款。

### 8.3 报告保存与数据控制

我的报告显示测评来源、生成时间、报告版本和当前权益。用户可以保存报告，分享前选择脱敏内容并预览；私人经历默认不进入分享卡。

原始答题、经历、报告和交易记录按既有数据规则分别管理。删除前展示影响，不用删除报告冒充退款，也不用退款冒充删除数据。

## 9. 职业探索功能 第二期

### 9.1 补充输入

用户补充职业兴趣、工作价值观、技能与熟练程度、教育和工作经历、当前目标、可投入时间、地点及收入等本人选择提供的现实条件。未提供的信息保持未知。

职业兴趣等量表同样优先使用成熟工具。不能只用 MBTI 类型或优势排名自动生成唯一职业答案。

### 9.2 交付结构

| 内容 | 用户得到什么 |
|---|---|
| 当前条件摘要 | 用户确认的经历、能力、偏好与约束 |
| 2～3 个探索方向 | 各方向的支持理由、冲突条件和仍需验证的假设 |
| 能力差距 | 已有依据、待补技能、需要作品或实践证明的部分 |
| 方向比较 | 工作内容、协作环境、投入要求和现实适配 |
| 30 天探索计划 | 小项目、访谈、课程试学或作品实践等可验证步骤 |
| 一次校准与复盘 | 核对建议是否符合实际；服务窗口同为 7 天 |

报告中的 30 天是用户可自行执行的计划长度，不代表包含 30 天连续陪伴。行业或岗位的时效性事实需记录来源和日期；无可靠依据时不提供精确薪酬、就业概率或录用承诺。

原基础报告与职业报告分别保留历史版本。升级只解锁新增交付，不要求重新购买已有基础内容。

## 11. 开发边界与验证方案

### 11.1 复用与必要扩展

复用现有身份、中央鉴权、Assessment、报告、商品、订单、支付、权益、退款和售后职责。复用指沿现有结构补齐行为，不代表尚未实现的模块已经可用。

必要变化包括多测评目录、结果组合快照、个人经历确认、自测报告来源以及新的报告模板和商品。自测报告直接关联结果快照；关系报告继续关联关系任务，不构造虚假的关系事件来生成优势报告。

原来“一个关系任务最多一个完整卡权益”的规则需要按来源解释：新的自测流程允许同一基础结果快照拥有基础和职业两种交付权益，同一商品交付仍只能有一个有效权益。通过商品、来源及版本明确归属，避免升级时覆盖基础权益。

身份和资源所有权由服务端执行；报告内容、支付事实和查看权益分别承担各自责任。计分与输入快照可复现，AI 用于受约束解释和建议。用户端只展示决策所需信息，不展示内部状态码和实现机制。

### 11.2 优先沿现有接口和真实页面验收

测试集中在外部可观察行为：测评接口、报告读取与权益接口、订单及支付通知边界，以及原生小程序路径。复用现有前端状态测试、页面烟测、API 集成和 E2E 入口。

| 场景 | 必须证明 |
|---|---|
| 免费完整路径 | 从任一新入口完成测评，真实页面显示基础结果并可继续免费使用 |
| 综合报告路径 | 选定结果、补充经历、确认信息、预览、单次购买、打开对应完整报告 |
| 计分一致性 | 相同版本和答案得到相同分数；缺失及反向计分按工具规则处理 |
| 个人化质量 | 相同人格类型但经历和目标不同的样例，建议确实依据不同输入变化 |
| 内容依据 | 重要结论有输入依据或待验证标注；没有虚构经历及百分位 |
| 支付故障 | 重复、乱序通知、金额不符、超时和查单不会误授予或重复授予权益 |
| 权限 | 未购、非本人及退款成功后的访问按对应权限返回 |
| 补差与退款 | 标准价、优惠价、退款中、已升级、仅退升级和整套退款均一致 |
| 7 天服务 | 校准成功、失败恢复、复盘和到期后的报告访问符合承诺 |
| 数据控制 | 分享预览、取消、导出和删除沿实际页面与后端路径一致 |

代码测试通过仅证明对应行为。功能完成还需同版本实际页面交付证据；真实商业验证以可核对的订单、净实收、退款和报告交付为准。

## 12. 运营、指标与商业验证

### 12.1 最小运营能力

- 测评管理：上下架、版本、供应商状态、题数和耗时说明。
- 报告管理：模板、样例、失败记录、重生成及修订版本。
- 商品管理：交付清单、价格版本、补差规则及服务窗口。
- 交易售后：订单、可信付款、权益、退款及交付异常。
- 数据面板：漏斗、净实收、退款、交付成本和复盘情况。

### 12.2 指标定义

| 指标 | 定义 |
|---|---|
| 自测开始用户 | 去重后主动开始一项测评的合格成年用户 |
| 单项完成率 | 有效完成该测评的用户／开始该测评的用户 |
| 有效付费曝光 | 已看到可交付报告的预览、价格和权益说明的去重用户 |
| 净付款转化率 | 观察期结束后仍有有效付费权益及正净支付金额的用户／有效付费曝光用户 |
| 净实收 | 已确认收款减已确认退款；未确认款项单列 |
| 交付成功率 | 已付款且可正常读取对应完整报告的订单／已付款订单 |
| 退款率 | 已发生退款的付款订单／付款订单，按统一观察窗口统计 |
| 行动与复盘 | 选择行动、提交实际结果及完成复盘的用户比例 |
| 单个自测用户贡献 | 净实收减渠道、全部免费及付费测评工具调用、内容生成、售后等可变成本，再除以自测开始用户数 |

按入口、人群需求、测评版本、价格、获客渠道和终端分组。同一实验采用一致观察窗口，保留流失、未付款及退款用户。分析事件仅包含必要标识和状态，不记录题目答案、经历或报告原文。

### 12.3 验证顺序与重判条件

先用完整报告样例及小规模封闭体验验证可理解性与具体价值，再验证真实交易。小样本体验不能证明量表信效度、市场规模或稳定转化率。

建议第一轮邀请 30 名目标用户完成体验，重点记录哪些解释符合事实、哪些建议愿意尝试、哪些内容与免费结果重复；记录拒绝付费的原因。具体收费实验沿既有发布与支付流程准备，不能把模拟付款作为真实支付意愿。

出现以下情况时重新判断方案：

- 用户普遍无法指出付费报告新增的具体价值：重做报告交付与预览。
- 大量用户在补充测评或经历时流失：检查最低输入和耗时，不能直接用不充分输入生成强结论。
- 支付成功但交付失败：先修复交付，再扩大转化实验。
- 净贡献持续为负：重新评估价格、成本或获客方式。
- 存在真实、重复的持续成长需求：再评估订阅和长期服务。

## 13. 评审与交付检查

本稿已覆盖功能入口、独立与综合测评、最低输入、报告目录、免费付费边界、单次购买、补差升级、服务窗口、异常和退款、个人数据、运营与验收。

开发前需要落实的配置包括：选用的具体测评版本与实际接入方式、商品最终测试价、目标人群招募方式、客服服务能力和对应支付渠道。授权采购由业务方处理，不要求本轮重新讨论。

本稿新增自我探索和职业探索规格，不自动改写现有关系产品的已批准需求，也不自动开启真实支付或发布。
